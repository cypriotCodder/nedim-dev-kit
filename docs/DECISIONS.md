# Architecture decisions

Newest at the top. Each entry is short and permanent. To change a decision, add a new entry that supersedes it. Don't edit old ones.

---

## ADR-015: osv-scanner adds only the ecosystems the package manager didn't audit  (2026-11-06, status: accepted; supersedes part of ADR-013)

**Context:** ADR-013 added osv-scanner's counts to the package manager's audit counts. The two overlap: an npm advisory both find was counted twice, and osv-scanner includes the dev dependencies that `npm audit --omit=dev` and `pnpm audit --prod` leave out on purpose. So a high advisory in a build tool failed the gate only on machines with osv-scanner installed.
**Decision:** When the package manager's audit ran, osv-scanner's `npm` packages are left out and its other ecosystems (a Python or Go part of the repo) are added. When there's no such audit (no lockfile, `bun.lock`, Cargo), osv-scanner's counts are used whole, as before. Its full report is still saved as `osv.json`.
**Alternatives:** Keeping osv-scanner's counts as context only (a vulnerable Python dependency beside a Node app would never reach the gate). Filtering osv-scanner to production dependencies (its JSON doesn't say which are dev dependencies for every lockfile).

## ADR-014: Exception paths are judged by their shape, and a plain path covers its folder  (2026-11-06, status: accepted; supersedes part of ADR-013)

**Context:** ADR-013 refused an exception path if it matched sample files with 14 common extensions. A review of PR 6 found that every other kind got through: `**/*.yaml`, `**/*.sh`, `**/*.pem` and `**/.env*` were all accepted, so one entry could accept every tracked `.env` file. The README also said a path could name a folder, but `tests/fixtures` matched no file under it.
**Decision:** A path is refused when its last part has a wildcard and every part before it is only wildcards (`**/*.yaml`, `*/*.ts`, `**/.env*`, `*.ts`). A path that names a folder or file anywhere in it is accepted (`fixtures/*.ts`, `**/fixtures/**`, `**/.env`). A path without wildcards also matches the files under it, and a trailing `/` is dropped.
**Alternatives:** More sample extensions (there's always one more). Building samples from the glob's own suffix (handles `*.yaml` but needs care for every glob form; the shape rule is simpler and covers them all). Changing the README to require `tests/fixtures/**` (the plain folder is what people write first).

## ADR-013: Evidence that can't be read is named, and accepted risks expire within a year  (2026-11-05, status: accepted)
**Context:** Some inputs gave wrong scores with no warning. A rule named `constructor` scored `NaN/10`. CI outside GitHub and GitLab got the `no-ci` cap. A tsconfig using `extends` read as unknown and quietly skipped `strict-off`. A broken `package.json` read as having no dependencies. A finding downgraded to `possible` showed as fixed. A summary copied into another clone was checked against the first clone's HEAD. PR 4 also left gate results that passed without having looked: no dependency audit, no gitleaks in CI, `--src` naming a missing folder, a crashed `npm outdated`. Exceptions could last forever (`9999-12-31`) or name every file of a type (`**/*.js`).
**Decision:** Rule lookups use own keys only. CI is detected for 15 systems, and `inventory.ci` names them. Strictness is its own `strict` tool, which follows `extends` (paths, packages and arrays) and project references without needing TypeScript. A config it can't parse applies `strict-off` as `not-ruled-out`, and one extending an uninstalled package is a gap. A broken `package.json` applies `no-lockfile` as `not-ruled-out`. Appendix findings keep earlier ids, are stored in `latest.json` and reported in `comparison.downgraded`. `summary.root` only counts when the summary or the current folder is inside it. The gate fails when online and dependencies exist but nothing could audit them, folds osv-scanner counts in, requires gitleaks when `CI` is set, and lists what a pass didn't assess. Secret names match wherever the secret word sits, and values are checked to rule out message keys, env references, paths, identifiers and settings. Redaction also covers URL passwords, `Bearer` tokens, newer key formats and unquoted `NAME=value`. UTF-16 files are scanned. Each run removes the outputs of the last one. Exception expiries must be within 366 days, paths are refused if they match random sample files with common extensions, and a leading `./` is dropped. `AGENT_DISCIPLINE_TOOL_TIMEOUT_MS` lowers every tool's time limit. These stay in rubric 2, which hasn't been released.
**Alternatives:** Applying `strict-off` when a base config isn't installed (every audit before `npm install` would be capped, which is the "skipped" case ADR-009 rejects). Wiping the whole output folder (`--out` can point anywhere). Allowing a longer expiry, such as two years (a yearly look is the point). Detecting CI from a folder existing (an empty `.github/workflows` would count).
**Consequences:** Projects that excepted a whole file type, or set expiries over a year ahead, now fail the gate until they narrow the entry. CI audits need osv-scanner for Bun and non-JavaScript dependencies, and gitleaks always. A real secret written as a dotted name, snake_case words or a path isn't caught by `hardcoded-secret` (provider formats still are). Redaction removes more harmless text from evidence, such as `token abc...` in prose.

## ADR-012: UI review reaches real pages, and skills trigger more narrowly  (2026-11-05, status: accepted)
**Context:** `ui-review` could only see public, light-mode pages at one hit-target size, and a very tall screenshot was too small to judge once scaled. Checkpoint ran the UI review after the independent review, so the reviewer never saw what it changed, and its `git diff --stat` missed new files. Broad skill descriptions fired on any mention of messy code or a UI complaint. These shipped on the audit-contract branch because they came out of the same review.
**Decision:** `screenshot.mjs` gains `--auth` (a Playwright storage state), `--dark-class`, tiled captures for tall pages, per-device hit-target sizes and optional `axe-core` checks, and it prints `REDIRECTED` when a page lands somewhere else. Checkpoint runs the UI review first and lists changes with `git status --porcelain --untracked-files=all` plus `git diff HEAD --stat`. `bootstrap` and `audit` set `disable-model-invocation`, and `design-system`, `ui-review` and `checkpoint` describe narrower triggers.
**Alternatives:** A separate PR for these (cleaner history, but the maintainer preferred one PR). Logging in from the script (it would have to handle passwords). Requiring `axe-core` (a new dependency for every project, so it's optional and its absence is reported).
**Consequences:** One PR covers two themes, so its diff is larger. Tiling and `--auth` are tested against a fake Playwright and still need a check against the real one (ADR-001). Skills with narrower triggers need asking for by name more often.

## ADR-011: Unknown results don't count as clean in scoring and doctor  (2026-11-05, status: accepted)
**Context:** A review of ADR-009 and ADR-010 found the same mistake repeatedly: no answer read as a good answer. Git being unavailable passed the stale-evidence check, zero anchors scored successfully, an auditor's own `possible` skipped verification, and only a merged finding's first location was checked against a risk. Doctor said `off` for a missing folder and for every package in a monorepo, `active` when it matched no hook scripts, and `active` for a copied collector that couldn't parse. Findings marked fixed never appeared as fixed.
**Decision:** `score.mjs` reads the project from `summary.root`, refuses evidence it can't compare with HEAD (a recorded commit with no readable HEAD, a failed git, or no commit when HEAD now exists), requires a score to exist, requires verification regardless of confidence, and makes locations project-relative, refusing any outside the project. A risk must cover every location of a finding, and a location only counts as covered if it exists in the project, which replaces guessing from its characters whether a string names one file. Lows fire no caps, because they aren't verified. Findings marked `fixed` are reported as fixed in every mode. Coverage gaps are counted beside the grade and don't change it, so ADR-009's rule for skipped tools stands. A skip is marked `notApplicable` by the collector only when it has shown there's nothing to look at, such as no TypeScript file anywhere for typecheck. A tool that can't reach what's there stays a gap. Doctor resolves typecheck per package and ESLint per binary and config, leaving out fixtures, templates and examples unless the project declares them as workspace packages, names what it left out, parses `hooks.json`, and treats ESLint that is asked for but not installed as broken. A CI gate copy of the current version must match the plugin's files, ignoring line endings, or it's broken. These stay in rubric 2, which hasn't been released.
**Alternatives:** Listing the characters that make a location prose (three review rounds each found another bypass, and it rejected real paths such as `app/(auth)/page.tsx`). Reporting an edited gate copy as `outdated` (exit 0, though it may not run). Running `node --check` on the copy (it catches syntax errors but not a broken import or changed logic). Lowering the score for skipped tools (ADR-009 rejected this). One ESLint sample per binary (a broken package config could hide behind a working one).
**Consequences:** A project that edits or reformats its gate copy shows as broken until it re-copies. Doctor runs one typecheck per package, so it takes longer on a monorepo, and it shares the audit's ignored folders, so a package under `build/` or `vendor/` shows as `off` though the hooks would check it. A hoisted ESLint 9 finds its flat config from the working folder, so doctor can't see a broken config in a package below it. Locations are split on commas, semicolons, newlines and " and ", and anything that isn't a real file stays open, which fails safe: that includes a finding about a file that's since been deleted, and a note after the path. Rewording a note with no line number changes the finding's id. A route written as `/api/login` looks like a path outside the project and is refused. Moving a summary to another machine falls back to the current folder.

## ADR-010: Doctor runs the guards instead of looking for their config  (2026-11-04, status: accepted)
**Context:** Most failures in the original review were guards that looked installed and did nothing. A check for whether a config file exists would repeat that mistake.
**Decision:** `doctor.mjs` runs the real typecheck and boundary check and loads the real ESLint config, then reports `active`, `off`, `broken` or `outdated`, exiting 1 on anything broken. A check that crashes counts as broken. A project's copy of the collector carries `KIT_VERSION` in `lib/version.mjs`, which doctor reads as text and doesn't import.
**Alternatives:** Checking only that files exist (fast, and misses a broken config). Publishing the collector as an npm package to handle versions (a release process for one script). Importing the project's copy to get its version (runs project code from a diagnostic).
**Consequences:** Doctor takes as long as a typecheck. It can't see whether Claude Code loaded the hooks, so it says to check `/hooks`.

## ADR-009: Scores are computed, and the model only chooses an anchor  (2026-11-04, status: accepted)
**Context:** The model applied the rubric's caps and arithmetic, invented rule names that finding ids depended on, verified a random third of mediums while the rubric counted only verified findings, and stored `GOOD:` notes as findings. Partial audits overwrote the baseline, so anything they didn't re-check looked fixed, and `--since-last` had no commit to diff against.
**Decision:** `score.mjs` takes one anchor per category and computes the rest, with caps and rule ids stored in `rules.json`. It refuses unknown rules, unverified critical, high or medium findings, and evidence from another commit. Only `mode: full` writes `latest.json` and `history.csv`. Every critical, high and medium finding gets verified. A tool that failed or timed out can't rule out its caps, so they apply, while a skipped tool is only reported as a gap. `rubricVersion` is stored with each audit, and scores from different versions aren't compared. Findings can be accepted in a `risks` list with the same reason and expiry as ADR-007, except critical ones. Auditors lose Bash, and `collect.mjs` captures the git history they read.
**Alternatives:** Stronger wording in `SKILL.md` (the original problem). Applying caps for skipped tools too (every local audit would be capped for not running tests, which ADR-008 makes opt-in). Free-form rule names with fuzzy matching (ids would still drift). Verifying a fixed sample of mediums (a medium's chance of counting would depend on the sample).
**Consequences:** Scores from version 1 aren't comparable, so the first audit after upgrading shows no trend. Verifying every medium costs more per audit. A problem that fits no rule uses `other-<category>`, matched on its title too, so rewording it gets a new id. A partial audit's new findings can get a different id at the next full audit. Plugin agents can't be sandboxed further, so removing Bash is what makes them read-only.

## ADR-008: Collected evidence is safe to keep, and collecting it is safe to run  (2026-11-04, status: accepted)
**Context:** `patterns.txt` stored matched lines, and CI uploaded all raw evidence as an artifact. ESLint's report holds a copy of each file with a problem, and jscpd's holds the duplicated code. `npx --yes` ran the latest release of each tool with the user's full environment, and `npm test` ran by default, which can hit a real dev database.
**Decision:** Every write goes through `redact()`, and the ESLint and jscpd reports lose their copies of the code. CI uploads only `summary.json`. npx tools are pinned, run with a short allowlist of environment variables and with install scripts off. Tests run only with `--tests`, `--gate` or in CI.
**Alternatives:** Redacting only `patterns.txt` (misses every other file that quotes code). No artifact at all (loses the summary a failed gate is debugged from). A blocklist of secret-looking variables (misses names it doesn't know).
**Consequences:** Redaction only knows the formats it's told about, so raw evidence still mustn't be committed. dependency-cruiser run through npx can't load the project's TypeScript and drops `.ts` files without saying so, so on a TypeScript project the boundary check reports `failed` unless it's installed locally. Pinned versions need updating on purpose, and a major update needs a run against the real tool, since knip 6 changed its report shape. Local audits report tests as not run until someone opts in.

## ADR-007: Secret findings are accepted in a committed file with a reason and an expiry  (2026-11-04, status: accepted)
**Context:** The gate failed on a fake token in a test and on `.env.development`, which frameworks expect to be committed, and nothing could accept a false positive. The only way out was turning the gate off.
**Decision:** `.audit-exceptions.json` accepts findings by rule and path, each with a reason and an expiry date. Accepted findings stay in the metrics and are listed in `metrics.exceptions`. An expired entry stops applying. A bad entry or an unreadable file fails the gate. `.env` and `*.local` always count as leaks; other env files count only when they hold a secret. A long string named `token` in a test is reported as a lead and doesn't block, while a real provider key format blocks anywhere.
**Alternatives:** Inline comments (scatter accepted risks, and can't go in a `.env` or JSON file). A list with no expiry (accepted risks never get looked at again). Ignoring a bad entry (a typo would surprise someone at the next release).
**Consequences:** Only secret and env findings can be accepted. A vulnerable dependency can't, because `npm audit` metadata gives counts and not advisories, and gitleaks has its own `.gitleaksignore`. Non-test code with a long fake token needs an entry. Env file checks read variable names, so a secret under an unusual name passes unless its value has a known key format.

## ADR-006: Design guard exceptions live in DESIGN.md  (2026-11-04, status: accepted)
**Context:** The guard told Claude a gradient was fine if `DESIGN.md` permitted it, but never read `DESIGN.md`. A brand that really uses Inter was flagged forever.
**Decision:** A comment in `DESIGN.md`, `<!-- design-guard: allow gradient, inter -->`, turns rules off by name. An unknown name warns the user once per session. The audit counts `design-guard-ignore` lines so one-line bypasses stay visible.
**Alternatives:** A separate config file (one more file, away from the decisions it records). Parsing the prose in `DESIGN.md` (unreliable).
**Consequences:** The guard stays regex heuristics. In plain `.ts` and `.js` files it only reads class helper calls that start inside the edit, so an edit inside an existing `cva()` call isn't scanned. `design-critic` and `ui-review` are the backstop.

## ADR-005: Stop checks follow session edits and compare against a baseline  (2026-11-04, status: accepted)
**Context:** Stop used `git status`, which missed work committed during the turn and files with quoted names, and sent Claude back on idle turns because of someone else's dirty files. It also told Claude it could call errors pre-existing, and never re-checked a fix.
**Decision:** `PostToolUse` records each edit in a session folder under the OS temp directory. Stop runs only for recorded edits, and blocks only on problems missing from a baseline. `PreToolUse` captures that baseline before the session first touches what a check covers. Stop re-checks after each attempt and gives up after three in a row, showing the user what's left. If the baseline couldn't be captured, every problem counts as new. This supersedes the "once per edit" consequence of ADR-004: a broken ESLint now warns once per session.
**Alternatives:** Capture at `SessionStart` (slows sessions that never edit, and a background capture can race the first edit). Capture at the first `PostToolUse` (too late: Claude's own errors would count as old). Only report errors in edited files (misses a changed export that breaks another file). Rebuild the old state from a git worktree at Stop (slow, and writes under `.git`).
**Consequences:** The first code edit of a session waits for a full typecheck. Edits made through Bash aren't recorded, so a turn with only those skips the checks; this is narrower than the old `git status` check for uncommitted work, and CI remains the backstop. Problems are matched on file, code and message without the line number, so a custom script's output in an unknown format is compared line by line and may count as new when it changes.

## ADR-004: Broken tools warn the user and don't block Claude  (2026-11-04, status: accepted)
**Context:** Hooks treated a crashed or timed-out tool as a pass. A broken tool says nothing about the code, and it's usually not something Claude caused.
**Decision:** In hooks, a tool that doesn't finish produces a `systemMessage` for the user and exit 0. In the CI gate, a required tool that doesn't finish fails the gate.
**Alternatives:** Exit 2 in hooks (sends Claude after an environment problem, on every edit). Staying silent (the original bug).
**Consequences:** A broken ESLint config warns on each edit until it's fixed. PR 3's session state could reduce that to once per session.

## ADR-003: Typecheck project references through temporary configs  (2026-11-04, status: accepted)
**Context:** On a references setup, tested on TypeScript 5.5 and 5.9: `tsc --noEmit` checks nothing, `tsc -p x --noEmit` reports TS6305 until references are built, and `tsc -b --noEmit` is rejected or reports TS6310. `tsc -b` works but writes build output, which a hook must not do.
**Decision:** For each config in the setup, generate a temporary one in `node_modules/.cache` that extends it, drops `references` and turns off `composite`, then run `tsc -p` on it. Imports resolve to source.
**Alternatives:** `tsc -b` (writes to the project). Copying the project to a temp folder (slow, and breaks `node_modules` resolution).
**Consequences:** Nothing is written outside `node_modules`, and no build is needed first. Referenced sources are compiled under the importing project's options, so projects with very different settings could see false errors. A custom `typecheck` script always wins over this, except a bare `tsc --noEmit`.

## ADR-002: Track known bugs as `todo` tests  (2026-11-04, status: accepted)
**Context:** A review flagged 25 issues, to be fixed over several PRs. Many are silent failures, where a broken guard looks the same as a passing one.
**Decision:** Write a failing test for each reproducible bug straight away. Mark it `todo` with the PR that will fix it, and remove the flag in that PR.
**Alternatives:** A written backlog (can't show that a bug is real or fixed). Leaving tests red until fixed (CI would be useless in the meantime).
**Consequences:** CI stays green while the backlog stays executable. A `todo` test doesn't fail the run when it starts passing, so each PR has to remove the flags it earns.

## ADR-001: Black-box tests with fake tools and no dependencies  (2026-11-04, status: accepted)
**Context:** The hook and audit scripts are about to be restructured, and they shell out to `tsc`, `eslint`, `semgrep` and others.
**Decision:** Use `node:test` and run scripts as subprocesses against temp projects, with small fake executables that return a chosen exit code.
**Alternatives:** Unit tests of internals (would break during the rewrite). Real tools in every test (slow, needs installs and network, and crashes are hard to trigger).
**Consequences:** Tests are fast and survive rewrites, and crashes and timeouts are easy to simulate. Fakes can drift from real tools, so each one encodes observed behaviour, and fixes that depend on a real tool also need a check against that tool.
